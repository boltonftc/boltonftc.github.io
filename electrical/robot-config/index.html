2hubs

You need two hubs. The robot has six motors and a Control Hub only has four motor ports, so the drivetrain goes on the Control Hub and the mechanisms go on an Expansion Hub. The exact port numbers are up to your wiring. What has to match is the name and the device type. If one doesn't, hardwareMap.get(...) throws an error and the OpMode won't start.

Before you save

Six things to double-check

  1. 1Names are case-sensitiveThey must match the code character for character: lowercase and underscores, with no spaces or capitals.
  2. 2Pick the right motor modelChoose your exact goBILDA motor when you add each one, so the encoder counts and speed limits are right.
  3. 3feeder is a CRServoAdd it as a Continuous Rotation Servo, or it will only twitch instead of spinning.
  4. 4pinpoint on I2C, not bus 0Add it as the goBILDA Pinpoint Odometry Computer device type (SDK 12.0+), on bus 1, 2 or 3.
  5. 5imu is usually already thereIt's the Control Hub's built-in IMU. If it's missing, add it on the Control Hub's I2C bus 0.
  6. 6Save, then activateActivate the configuration after you save it, then restart your OpMode.

Why does bus 0 matter? See Electrical Gremlins → Port gotchas.
