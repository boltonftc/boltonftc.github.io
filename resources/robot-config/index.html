These are the exact device names to enter in the Driver Hub → Configure Robot screen for our BIOBUZZ robot. Every name below is read directly from our finished code, so the spelling has to match exactly — all lowercase, underscores (_) between words, no spaces. If a name doesn't match, hardwareMap.get(...) throws and the OpMode won't start.

You need two hubs. This robot has 6 motors, but a Control Hub only has 4 motor ports — so the drivetrain + one mechanism go on the Control Hub and the rest on an Expansion Hub. Exact port numbers are up to your wiring; what matters is that the name and device type match this table.

Before you save the configuration

  • Names are case-sensitive and must match the code character-for-character: lowercase, underscores, no spaces or capital letters.
  • Motors: pick the correct goBILDA motor model when adding each one so the encoder counts and speed limits are right.
  • feeder must be added as a Continuous Rotation Servo (CRServo), or it won't spin continuously.
  • pinpoint is added on an I2C bus as the goBILDA Pinpoint Odometry Computer device type (available in SDK 12.0).
  • imu is the Control Hub's built-in IMU — on most configs it's already present as imu; if not, add it on the Control Hub's I2C bus 0.
  • After saving, activate the configuration and re-run your OpMode.
